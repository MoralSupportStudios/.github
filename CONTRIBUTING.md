# Contributing to Moral Support Studios

We build in the open, and we've got your back. Whether you're here to play,
report a bug, pitch an idea, or write code — thanks for showing up. This guide
applies across all Moral Support Studios repositories; individual projects may
add their own notes in their README.

## Ways to help

- 🎮 **Playtest.** Grab the latest build, play it, and tell us what broke or
  what felt great. Honest reactions are gold.
- 🐛 **Report bugs.** Open an issue using the bug / playtest template in the
  relevant repo. Include your version, what you did, and what happened.
- 💡 **Suggest features.** Use the feature request template. Tell us the
  problem you hit or the moment you wish existed — not just the solution.
- 🛠️ **Contribute code or assets.** See below.

## Filing a good issue

- One issue per problem or idea.
- Search open issues first so we can pile onto an existing thread instead of
  splitting the conversation.
- Screenshots, clips, and logs make everything faster.

## Code & asset contributions

1. Branch off `main` (fork first if you're not on the team).
2. Keep changes focused — smaller PRs get reviewed faster.
3. Open a pull request and fill out the template. Link the issue it addresses.
4. For gameplay changes, a short clip or before/after screenshot lets us review
   without rebuilding locally.

We review on a best-effort basis — we're a small studio. If a PR's been quiet
for a while, a polite nudge is welcome.
