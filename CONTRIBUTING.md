# Contributing to Moral Support Studios

> We've got your back — and we'd love yours.

Thanks for taking the time to help out! Whether you're reporting a crash you hit
mid-playtest, pitching a wild feature idea, or fixing a typo, you're welcome
here. This guide covers how we like to work across all Moral Support Studios
repositories.

## Ways to contribute

You don't have to write code to be a huge help:

- 🐛 **Report bugs & playtest feedback** — the single most valuable thing you can
  do. Use the **[playtest bug](https://github.com/MoralSupportStudios/Space-Game/issues/new?template=playtest-bug.yml)**
  template so we get everything we need to reproduce it.
- 💡 **Suggest features** — use the **[feature request](https://github.com/MoralSupportStudios/Space-Game/issues/new?template=feature-request.yml)**
  template.
- 📣 **Spread the word** — tell a friend, post a clip, leave a comment on itch.
- 🛠️ **Write code** — see below.

## Reporting a good bug

The best bug reports let us reproduce the problem without guessing. Please
include:

1. **What you expected** to happen, and **what actually** happened.
2. **Steps to reproduce** — as exact as you can manage.
3. **Build version** (shown in-game / on the itch download).
4. **Platform** — OS, single-player vs. online vs. LAN, and how many players.
5. **Screenshots, clips, or logs** if you have them — a 5-second clip is worth a
   thousand words.

## Contributing code

1. **Open an issue first** for anything non-trivial so we can agree on the
   approach before you sink time into it. Small fixes (typos, obvious bugs) can
   skip straight to a PR.
2. **Fork & branch.** Create a focused branch off the default branch — one
   logical change per branch (e.g. `fix/airlock-desync`, `feat/co-op-respawn`).
3. **Keep PRs small and scoped.** Smaller PRs get reviewed faster and merge
   sooner.
4. **Write a clear PR description.** Explain *what* changed and *why*. Link the
   issue it closes (`Closes #123`). The PR template will prompt you.
5. **Be kind in review.** We give feedback to make the work better, never to
   make anyone feel small.

### Commit messages

Write commit messages that explain the *why*, not just the *what*. A short
imperative summary line (e.g. `Fix airlock desync on host migration`) followed
by a paragraph of context when it helps is perfect.
